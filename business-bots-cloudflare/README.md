# ربات‌های فروشگاه و منشی روی Cloudflare Workers

دو ربات تلگرام — **ربات فروشگاه** (کاتالوگ، رسید، کد تخفیف، اشتراک، گارانتی) و **ربات منشی** (Business Chat Automation، FAQ، ساعت کاری، Gemini، سفارش‌ها) — داخل **یک Cloudflare Worker** اجرا می‌شوند. سرور، VPS یا PM2 لازم نیست و همیشه روشن‌اند.

> برنامه‌ی کامل طراحی در [`PLAN.md`](./PLAN.md) است. این فایل فقط راهنمای راه‌اندازی و نگهداری است.

## معماری در یک نگاه

```
تلگرام ──► POST /tg/store   ──► ربات فروشگاه ─┐
تلگرام ──► POST /tg/monshi  ──► ربات منشی   ──┤  (ارتباط مستقیم، بدون کانال پل)
مرورگر ──► GET  /setup?key= ──► ثبت webhook هر دو ربات
Cron هر دقیقه ──► یادآوری اشتراک، هشدار سفارش معطل، صف اطلاعیه، دایجست شنبه‌ها

دیتابیس‌ها: STORE_DB و MONSHI_DB (Cloudflare D1)
```

| قبلاً | حالا |
|---|---|
| Long polling | Webhook (تلگرام خودش پیام را به Worker می‌فرستد) |
| فایل SQLite | Cloudflare D1 (دو دیتابیس جدا) |
| `setInterval` / JobQueue | یک Cron Trigger (`* * * * *`) |
| کانال خصوصی پل | فراخوانی مستقیم دو ربات (در یک Worker) |
| نشست‌های حافظه‌ای | نشست در D1 (با ری‌استارت از بین نمی‌روند) |

متن پیام‌ها، دکمه‌ها و ترتیب مراحل **دقیقاً مثل قبل** است. تغییرهای عمدی: پل مستقیم، ارسال اطلاعیه به‌صورت صف‌دسته‌ای، و ذخیره‌ی embeddingها با ۷۶۸ بُعد (در اولین پیام خودکار دوباره ساخته می‌شوند).

## پیش‌نیازها

- Node.js 18 یا بالاتر، و Python 3 (فقط برای انتقال دیتای قدیمی)
- یک حساب Cloudflare (پلن رایگان کافی است)
- توکن هر دو ربات از [@BotFather](https://t.me/BotFather). برای ربات منشی در BotFather: `Bot Settings → Business Mode → Turn on`
- آیدی عددی ادمین‌ها (از [@userinfobot](https://t.me/userinfobot))
- (اختیاری) کلید Gemini از [aistudio.google.com/apikey](https://aistudio.google.com/apikey)

## راه سریع (پیشنهادی): یک دستور

```bash
npm i
npm run setup
```
اسکریپت فقط توکن دو ربات، آیدی ادمین‌ها و (اختیاری) کلید Gemini و فایل‌های دیتابیس قدیمی را می‌پرسد و بقیه را خودش انجام می‌دهد: ورود به کلودفلر، ساخت دیتابیس‌ها، پر کردن `wrangler.toml`، ثبت توکن‌ها، ساخت جدول‌ها، انتقال دیتا، deploy و وصل webhook. بعدش فقط دو کار داخل تلگرام می‌ماند (Business Mode و اتصال منشی به حساب). برای دیدن مراحل بدون اجرا: `npm run setup -- --dry-run`. اجرای دوباره‌اش بی‌خطر است. مراحل دستی زیر فقط برای کسی است که ترجیح می‌دهد خودش انجام دهد.

## راه‌اندازی قدم‌به‌قدم (دستی)

همه‌ی دستورها را داخل پوشه‌ی `business-bots-cloudflare` و روی کامپیوتر خودتان اجرا کنید.

### ۱. نصب
```bash
npm i
npx wrangler login
```

### ۲. ساخت دو دیتابیس D1
```bash
npx wrangler d1 create store-bot-db
npx wrangler d1 create monshi-bot-db
```
هر دستور یک `database_id` چاپ می‌کند. هر کدام را در `wrangler.toml` جای مقدار موقتِ همان دیتابیس بگذارید (`STORE_DB` و `MONSHI_DB`).

### ۳. تنظیم ادمین‌ها
در بخش `[vars]` فایل `wrangler.toml`:
```toml
STORE_ADMIN_IDS = "123456789,987654321"   # ادمین‌های فروشگاه (چند نفر با کاما)
MONSHI_ADMIN_USER_ID = "123456789"        # مالک حساب Business (همان که منشی را وصل می‌کند)
MONSHI_NOTIFY_USER_IDS = ""               # اختیاری: حساب‌هایی که فقط نوتیف می‌گیرند
```
اگر خالی بمانند، ربات مربوطه غیرفعال است و `/setup` دلیلش را گزارش می‌دهد.

### ۴. ثبت secretها
```bash
openssl rand -hex 32     # خروجی را برای WEBHOOK_SECRET نگه دارید
npx wrangler secret put STORE_BOT_TOKEN
npx wrangler secret put MONSHI_BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put GEMINI_API_KEY      # اختیاری؛ بدون آن فقط تطبیق کلیدواژه‌ای کار می‌کند
```
توکن‌ها و کلیدها را **هرگز** داخل گیت نگذارید.

### ۵. ساخت جدول‌ها
```bash
npm run db:migrate:remote
```

### ۶. Deploy
```bash
npm run deploy
```
آدرس چاپ‌شده (مثل `https://business-bots.<subdomain>.workers.dev`) را یادداشت کنید.

### ۷. انتقال دیتای فعلی (فروشگاه و منشی)
1. ربات‌های قدیمی را **خاموش** کنید (سایت AlwaysData / `systemctl stop monshi-bot`).
2. فایل‌های `storefront.db` و `monshi.db` را **همراه با `-wal` و `-shm`** دانلود کنید (آخرین نوشته‌ها در همین فایل‌هاست).
3. تبدیل به SQL:
   ```bash
   python3 scripts/sqlite_to_d1.py --store /path/storefront.db --monshi /path/monshi.db --out-dir migration_out
   ```
   تعداد ردیف‌های هر جدول چاپ می‌شود؛ با دیتای واقعی‌تان مقایسه کنید.
4. ورود به D1:
   ```bash
   npx wrangler d1 execute store-bot-db  --remote --file=migration_out/store_data.sql
   npx wrangler d1 execute monshi-bot-db --remote --file=migration_out/monshi_data.sql
   ```
5. پوشه‌ی `migration_out/` شامل اطلاعات مشتریان است؛ بعد از اتمام پاکش کنید و **هرگز commit نکنید**.

> اگر از صفر شروع می‌کنید این مرحله را رد کنید.

### ۸. وصل کردن webhook
یک بار در مرورگر باز کنید:
```
https://<آدرس-worker>/setup?key=<WEBHOOK_SECRET>
```
خروجی JSON باید برای هر دو ربات `"ok": true` نشان دهد و `problems` خالی باشد. تلگرام پیام‌هایی را که در زمان خاموشی ربات‌ها صف شده بود (تا حدود ۲۴ ساعت) همان لحظه تحویل می‌دهد.

### ۹. تست
- در ربات فروشگاه `/start` بزنید (ادمین پنل مدیریت می‌گیرد، مشتری کاتالوگ).
- از یک اکانت دیگر به حساب پشتیبانی پیام بدهید و پاسخ خودکار منشی را ببینید.
- در ربات منشی `/status` بزنید.
- اگر حساب Business قبلاً وصل بود، دوباره از **Settings → Chat Automation** وصلش کنید تا `business_connection` جدید به Worker برسد.

### ۱۰. پایش
```bash
npx wrangler tail                 # لاگ زنده
```
داشبورد Cloudflare: Workers → business-bots → Logs / Metrics، و D1 → Metrics (تعداد ردیف‌های خوانده/نوشته‌شده).

## فیچرهای جدید

> بعد از دریافت این نسخه، **اول** `npm run db:backup`، بعد `npm run db:migrate:remote` (دو مایگریشن جدید: `store/0002_features.sql` و `monshi/0003_features.sql`) و در آخر `npm run deploy` (یا دوباره `npm run setup`). داده‌ی فعلی دست نمی‌خورد؛ همه‌ی ستون‌های جدید مقدار پیش‌فرض دارند.

### ربات فروشگاه

**ویرایش محصول** — پنل ادمین ← «✏️ ویرایش محصول». نام، قیمت، شرایط، مدت اشتراک و گارانتی را بدون حذف محصول عوض کنید. شناسه‌ی محصول ثابت می‌ماند، پس دکمه‌ی «🔄 تمدید» در یادآوری‌های قبلی کار می‌کند. سفارش‌های قبلی تغییری نمی‌کنند (قیمت و مدت‌ها روی سفارش ذخیره شده‌اند). اگر قیمت جدید کمتر از مبلغِ یک کد تخفیفِ «مبلغ ثابت» شود، هشدار می‌گیرید.

**ناموجود** — در همان صفحه‌ی ویرایش، «⛔️ ناموجود کن». محصول در لیست مشتری با برچسب «ناموجود» می‌ماند و قابل خرید نیست؛ مشتری می‌تواند «🔔 موجود شد خبرم کن» بزند. وقتی دوباره «✅ موجود کن» را بزنید، دکمه‌ی «📣 به N نفر در لیست انتظار خبر بده» می‌آید. رسیدی که مشتری قبل از ناموجود شدن پرداخت کرده، پذیرفته می‌شود.

**اطلاعیه‌ی هدفمند** — «📢 اطلاعیه‌ها» حالا اول می‌پرسد برای چه کسانی: همه، اشتراک فعال، اشتراک تمام‌شده، خریداران یک محصول، یا کسانی که هنوز خرید نکرده‌اند. تعداد گیرنده‌ها قبل از ارسال نشان داده می‌شود.

**دلیل رد رسید** — «❌ رد پرداخت» حالا دلیل می‌پرسد (مبلغ اشتباه، رسید ناخوانا، واریز نرسیده، کارت اشتباه، رسید تکراری، دلخواه یا بدون دلیل). مشتری دلیل را می‌بیند و دکمه‌ی «📸 ارسال مجدد رسید» می‌گیرد (برای «رسید تکراری» نه).

**تشخیص رسید تکراری** — اگر **همان فایل** رسید قبلاً برای سفارش دیگری آمده باشد، روی رسید ادمین هشدار ⚠️ می‌آید (ردِ خودکار انجام نمی‌شود، تصمیم با شماست). *محدودیت:* اگر کسی از رسید دوباره اسکرین‌شات بگیرد، فایل جدید حساب می‌شود و تشخیص داده نمی‌شود. زیر هر رسید هم «🧾 سابقه: N خرید تأییدشده» یا «🆕 اولین خرید این مشتری» نوشته می‌شود.

**«📋 اشتراک‌های من»** — سفارش‌های در انتظار بررسی، تأییدشده (در حال آماده‌سازی) و رد‌شده‌ی ۷ روز اخیر (با دلیل و دکمه‌ی ارسال مجدد) هم نشان داده می‌شوند.

**گزارش فروش** — «📊 گزارش فروش» ← امروز، ۷ روز، ۳۰ روز، ماه شمسی جاری، کل: درآمد، تعداد سفارش، پرفروش‌ها، رسیدهای ردشده، مشتری جدید، دعوت‌های موفق و وضعیت فعلی صف. *نکته:* سفارشی که در منشی لغو شود در فروشگاه «تأییدشده» می‌ماند (ادمین‌ها پیام می‌گیرند) و در شمارش «منتظر تحویل» هم می‌آید تا دستی رسیدگی شود.

**دعوت دوستان (Referral)** — «🎁 دعوت دوستان» در پنل ادمین. همه‌چیز قابل تنظیم است:
- تعداد دعوت موفق برای هر جایزه (مثلاً ۳)، حداقل مبلغ خرید دوست، تکرار جایزه (هر N دعوت یا فقط یک بار)
- نوع جایزه: **کد تخفیف شخصی** (درصدی یا مبلغ ثابت، برای یک محصول، با مدت اعتبار) یا **یک محصول رایگان** (سفارش تأییدشده‌ی ۰ تومانی که مثل بقیه از مسیر منشی تحویل داده می‌شود)
- روشن/خاموش با دکمه؛ تا محصول جایزه انتخاب نشده روشن نمی‌شود. با تغییر نوع جایزه، برنامه تا کامل شدن تنظیم خودش خاموش می‌شود.

مشتری وقتی برنامه روشن باشد دکمه‌ی «🎁 دعوت دوستان» می‌گیرد: لینک شخصی، قوانین، وضعیت و جایزه‌هایش. قواعد ضد تقلب: دعوت فقط برای **کاربر کاملاً جدید** (کسی که قبلاً ربات را استارت نزده)، فقط وقتی **اولین خرید دوست تأیید شود** (رسید یا خرید دستی)، هر نفر فقط یک بار دعوت می‌شود و کد تخفیف جایزه فقط برای خود معرف و یک‌بارمصرف است (در لیست کدهای ادمین دیده نمی‌شود).

### ربات منشی

**جدا کردن پیام‌ها با تاپیک** — اول در @BotFather برای **ربات منشی** حالت تاپیک (Threaded Mode) را روشن کنید. بعد در ربات منشی: ⚙️ تنظیمات ← «🗂 دسته‌بندی پیام‌ها». چهار تاپیک ساخته می‌شود: 🔔 پیام‌های نیازمند پاسخ، 📦 سفارش‌ها، 📊 گزارش‌ها، ⚙️ سیستم و اتصال. اگر تاپیکی را پاک کنید دوباره ساخته می‌شود. ربات فروشگاه عمداً تاپیک ندارد (چت مشتری‌ها هم تاپیکی می‌شد).

**کارت مشتری** — زیر هر پیامِ ارجاع‌شده، سابقه‌ی خرید و اشتراک فعال همان مشتری در فروشگاه نوشته می‌شود. با `/customer <@یوزرنیم یا آیدی>` هم می‌توانید کارت + آخرین پیام‌ها را ببینید.

**جواب از داخل نوتیف** — روی پیام ارجاع **Reply** بزنید (متن، عکس، فایل، ویس یا استیکر)؛ ربات از طرف اکانت بیزینس شما برای مشتری می‌فرستد، یک 👍 می‌گذارد و (طبق تنظیم `reply_bridge_pause`، پیش‌فرض روشن) ربات برای آن چت مثل جواب دستی ساکت می‌شود. اکانت‌های نوتیف هم می‌توانند. زیر نوتیف تا ۳ دکمه‌ی «📚 …» با FAQهای احتمالاً مرتبط هم می‌آید؛ با یک ضربه جواب FAQ ارسال می‌شود. *محدودیت تلگرام:* فقط به چت‌هایی می‌شود جواب داد که در **۲۴ ساعت گذشته** پیام داده‌اند و مجوز «پاسخ‌گویی» در اتصال بیزینس باید روشن باشد؛ وگرنه ربات دلیل را می‌گوید. لینک «نوتیف ← مشتری» ۳۰ روز نگه داشته می‌شود.

**یادگیری از جواب‌های خودتان** — در «📥 بی‌پاسخ‌ها» و دایجست هفتگی، برای سؤالی که خودتان دستی جوابش را داده‌اید (تا ۲۴ ساعت بعد از سؤال) جوابتان نشان داده می‌شود و دکمه‌ی «⚡️ FAQ با جواب خودم» با یک ضربه FAQ می‌سازد (فقط کلیدواژه‌ها را می‌پرسد). جواب‌های شخصی (رمز، شماره‌ی بلند، ایمیل، «user:/pass:»، خیلی کوتاه) هرگز پیشنهاد نمی‌شوند.

## API تأمین‌کننده (خرید و تحویل خودکار)

ربات فروشگاه می‌تواند اکانت‌ها را خودکار از یک تأمین‌کننده (فعلاً آریوباکس) بخرد و بعد از تأیید رسید برای مشتری بفرستد. محصولاتی که تأمین‌کننده ندارند **مثل قبل** کار می‌کنند: منشی، لینک خرید دستی و جایزه‌ی دعوت دوستان دست نمی‌خورند.

> **اول بخوانید:** این بخش به یک مایگریشن جدید نیاز دارد. به ترتیب: `npm run db:backup` ← `npm run db:migrate:remote` (فایل‌های `store/0003_supplier.sql` و `store/0004_supplier_report_indexes.sql`) ← `npm run deploy`. بعد از آن پنل «🔌 API تأمین‌کننده» را در پنل ادمین می‌بینید.

### راه‌اندازی
1. **افزودن تأمین‌کننده:** «🔌 API تأمین‌کننده» ← «🏪 تأمین‌کننده‌ها» ← «➕ افزودن تأمین‌کننده». نام، آدرس (پیش‌فرض را می‌توانید قبول کنید)، **کلید API** و `user_id` را می‌پرسد. ربات پیامی که کلید در آن است را **پاک می‌کند** و فقط چهار نویسه‌ی آخر کلید را نشان می‌دهد. بعد از ذخیره، اتصال و کاتالوگ یک بار آزمایش می‌شود.
2. **سود پیش‌فرض:** «💹 سود پیش‌فرض» ← درصد و/یا مبلغ ثابت. برای هر گزینه می‌توانید سود اختصاصی بگذارید.
3. **وارد کردن محصول:** از کارت تأمین‌کننده «📋 محصولات» ← محصول را بزنید. مدت اشتراک، گارانتی و عنوان گزینه‌ها **خودکار پر می‌شود و قبل از ساخت نشانتان داده می‌شود**؛ می‌توانید نام گروه، عنوان‌ها، مدت‌ها، سود و شرایط را عوض کنید و با «✅ ساخت محصول» بسازید. از «🔌 منابع و قیمت» هر گزینه می‌توانید منبع پشتیبان اضافه کنید.

### مشتری چه چیزی می‌بیند
- محصولی که چند گزینه دارد (مثلاً «ChatGPT Plus») اول به‌عنوان یک محصول نشان داده می‌شود و بعد مدت را می‌پرسد: «۱ ماهه / ۳ ماهه / …». این برای محصولات معمولی هم کار می‌کند.
- بعد از تأیید رسید پیام «اکانت شما در حال آماده‌سازی است…» (حداکثر تا ۲۴ ساعت) می‌بیند و **همین‌جا در ربات فروشگاه** اطلاعات اکانت برایش می‌آید.
- اطلاعات اکانت را بعداً هم از «📋 اشتراک‌های من» ← «🔑 نمایش اطلاعات اکانت» می‌تواند ببیند.

### قیمت و موجودی
- **قیمت فروش** = `قیمت دلاری × نرخ دلار خود API (usd_toman)` ← `× (۱ + درصد سود) + مبلغ ثابت` ← **گرد به بالا تا نزدیک‌ترین ۱۰٬۰۰۰ تومان**. اگر روی گزینه سود اختصاصی نگذاشته باشید، سود پیش‌فرض اعمال می‌شود؛ اگر هیچ‌کدام تنظیم نباشد، قیمت همان می‌ماند.
- هر ۱۰ دقیقه قیمت، موجودی و مشخصات از تأمین‌کننده گرفته می‌شود و قیمت گزینه‌های «خودکار» به‌روز می‌شود. اگر مشخصات محصول در تأمین‌کننده عوض شود، فقط **به شما خبر داده می‌شود**.
- اگر دستی قیمت یک گزینه‌ی خودکار را عوض کنید، ربات می‌پرسد «قیمت ثابت شود؟»؛ با «بله» آن گزینه دیگر خودکار قیمت نمی‌گیرد.
- هر گزینه یک **منبع اصلی** و هر چند **منبع پشتیبان** (حتی از تأمین‌کننده‌ی دیگر) دارد. ربات از اولین منبع **فعال و موجود** به ترتیب اولویت (اصلی اول) می‌خرد؛ اگر منبعی «ناموجود» جواب داد، سراغ بعدی می‌رود. گزینه فقط وقتی «ناموجود» می‌شود که **همه‌ی منبع‌هایش** ناموجود باشند.
- **کف سود:** کد تخفیفی که قیمت را زیر قیمت خرید ببرد ساخته نمی‌شود و مشتری هم نمی‌تواند واردش کند. سفارشی که با قیمت فعلی ضررده باشد خودکار خریده نمی‌شود و کارت تصمیم برایتان می‌آید.

### کارت «⏸ نیازمند تصمیم»
وقتی ربات نتواند سفارش را خودکار تمام کند، این کارت با آیدی مشتری و دلیل برای ادمین‌ها می‌آید (هم‌چنین در «🔌 API تأمین‌کننده» ← «⏸ نیازمند تصمیم»). اگر منبعی موقتاً ناموجود یا مشغول باشد، ربات تا ۲۰ ساعت هر ۱۵ دقیقه خودش دوباره امتحان می‌کند. دکمه‌ها:

| دکمه | کار |
|---|---|
| 🔁 تلاش دوباره | دوباره از همان منبع‌ها سفارش می‌دهد (برای ضررده یا جایزه‌ی دعوت، اول تأیید می‌گیرد) |
| 🔀 خرید از منبع دیگر | یک منبع را انتخاب کنید (حتی غیرفعال یا یک آیتم تازه از کاتالوگ) |
| 📦 از اکانت‌های من | یک اکانت آزاد از موجودی خودتان برای مشتری فرستاده می‌شود |
| ✍️ ارسال متن اکانت | متنی که می‌نویسید برای مشتری فرستاده می‌شود |
| 🙋 خودم تحویل می‌دهم | بعد از تحویل «✅ تحویل شد» را بزنید (با «↩️ برگشت به تحویل خودکار» تا قبل از هر تحویل می‌توانید پشیمان شوید) |
| ❌ لغو سفارش | با دلیل؛ کد تخفیف به مشتری برمی‌گردد، اگر این سفارش دعوتی را تأیید کرده بود از شمارش خارج می‌شود، مشتری پیام می‌گیرد و «بازپرداخت در انتظار» ثبت می‌شود تا «✅ بازپرداخت انجام شد» را بزنید |
| 💬 چت با مشتری / ✉️ پیام از طرف ربات | اگر مشتری یوزرنیم ندارد |
| 📜 تاریخچه | همه‌ی کارهایی که ربات یا ادمین‌ها روی سفارش کرده‌اند |

دستور `/order 1234` (یا `/order_1234`) کارت و تاریخچه‌ی هر سفارش را نشان می‌دهد. پیام «تحویل شد» برای ادمین‌ها منبع، قیمت فروش، هزینه و سود را دارد.

### پول: «هرگز دوبار شارژ نمی‌شوید»
- فقط **یک** جای کد می‌تواند سفارش بفرستد و آن هم فقط بعد از اینکه سفارش را به‌صورت اتمی «قفل» کرده باشد؛ پس تأیید دوباره‌ی رسید، دو ادمین هم‌زمان، وب‌هوک و Cron هرگز دو بار نمی‌خرند.
- اگر ارتباط وسط ثبت سفارش قطع شود (timeout، خطای ۵xx، پاسخ بدون شماره‌ی سفارش، یا خودِ Worker وسط کار بمیرد) **معلوم نیست سفارش ثبت شده یا نه**. ربات در این حالت **دوباره سفارش نمی‌دهد**، سفارش را `نامشخص` می‌کند و می‌پرسد: «ثبت شده بود؛ شماره‌اش را وارد می‌کنم» (از پنل تأمین‌کننده دنبال یادداشت `store#<شماره>/so#…` بگردید) یا «ثبت نشده بود؛ دوباره ثبت کن» (با هشدار).
- رد شدن‌های مشخص (ناموجود، کلید اشتباه، سفارش نامعتبر) پولی نمی‌برند و امن دوباره امتحان می‌شوند.
- **کیف پول** پیش‌پرداخت است و API راهی برای دیدن موجودی ندارد؛ پس ربات یک **موجودی تخمینی** نشان می‌دهد: جمع شارژهایی که ثبت می‌کنید (`💳 ثبت شارژ کیف پول`) منهای خریدها. «🧾 تاریخچه‌ی کیف پول» آخرین ۱۰ ردیف را دارد و برای بازگشت وجه یا اصلاح دستی دکمه دارد. اگر خرید به‌خاطر موجودی رد شود و تخمین هم کمتر از هزینه باشد، کارت همین را می‌گوید. تخمین **هیچ‌وقت جلوی خرید را نمی‌گیرد**.

### اکانت‌های خودتان
- «🛒 خرید مستقیم»: تأمین‌کننده ← گزینه ← تعداد (۱ تا ۱۰) ← تأیید. جواب **فقط برای ادمینی که خرید را زده** می‌آید و بدون تلاش خودکار است (اگر ناموفق بود دکمه‌ی «🔁 دوباره» می‌گیرید).
- «📦 اکانت‌های من»: دسته‌ها و اکانت‌ها. هر اکانت: «📤 ارسال برای مشتری» (شناسه یا @username، محصول و قیمت؛ سفارش ساخته و اکانت تحویل می‌شود)، «🔗 لینک خرید دستی»، «💰 فروختم بیرون از ربات» (قیمت)، «⚠️ خراب/مرجوعی». روی هر دسته می‌توانید **سود کل دسته** را (حتی منفی) و یادداشت ثبت کنید.
- **لینک خرید دستی** برای محصولی که تأمین‌کننده دارد یک سؤال اضافه می‌پرسد: خودم تحویل داده‌ام (مثل قبل) / از اکانت‌های من / خرید از تأمین‌کننده وقتی مشتری لینک را زد. حالت آخر هزینه را از کیف پول می‌زند و ساعت اشتراک از لحظه‌ی تحویل شروع می‌شود.
- **جایزه‌ی محصول رایگان دعوت دوستان** اگر محصولش از تأمین‌کننده باشد، خودکار نمی‌خرد؛ کارت «✅ تأیید و خرید» برایتان می‌آید.

### گزارش فروش
«📊 گزارش فروش» این خط‌ها را هم (وقتی چیزی برای نشان دادن باشد) دارد: 💵 هزینه‌ی خرید، 📈 سود سفارش‌های ربات (و تعداد سفارش‌هایی که هزینه‌شان ثبت نشده)، ❌ لغوشده و بازپرداخت‌های در انتظار، 🛍 فروش بیرون از ربات (درآمد و سود)، 📦 خرید برای موجودی، 💳 خرج کیف پول (دلار). سفارش لغوشده از درآمد خارج می‌شود.

### به‌روزرسانی
```bash
npm run db:backup            # پشتیبان کامل، همیشه اول
npm run db:migrate:remote    # مایگریشن‌ها (خودش هم قبلش بکاپ می‌گیرد)
npm run deploy
```

### امنیت
- کلید API در جدول `suppliers` دیتابیس D1 ذخیره می‌شود و **در پشتیبان‌ها هم هست**؛ پوشه‌ی `backups/` را خصوصی نگه دارید و commit نکنید. فقط در هدر `X-Api-Key` می‌رود، نه در آدرس و نه در لاگ.
- اگر کلید لو رفت، **در سایت تأمین‌کننده کلید را عوض کنید**، بعد از «🔌 API تأمین‌کننده» ← تأمین‌کننده ← «🔑 تغییر کلید» کلید تازه را وارد کنید.
- فرض‌های هنوز تأییدنشده با API واقعی (نحوه‌ی خطای کیف پول، واحد `price` در پاسخ، وضعیت‌های سفارش) در `SUPPLIER_PLAN.md` ← «پیوست A» نوشته شده‌اند؛ **قبل از اولین خرید واقعی** با یک سفارش کم‌هزینه بررسی‌شان کنید.

## پشتیبان‌گیری از دیتابیس (Backup)
قبل از هر deploy یا تغییر دیتابیس، از هر دو دیتابیس یک خروجی کامل (ساختار + داده) بگیرید:
```bash
npm run db:backup
```
فایل‌ها در پوشه‌ی `backups/` با نام `<دیتابیس>-<تاریخ>-<ساعت>.sql` ذخیره می‌شوند (در `.gitignore` است؛ شامل اطلاعات مشتریان است، **هرگز commit نکنید** و جای امنی نگه دارید).
- `npm run db:migrate:remote` اول خودش همین پشتیبان را می‌گیرد و اگر ناموفق باشد ادامه نمی‌دهد.
- `npm run setup` هم وقتی از دیتابیس موجود استفاده می‌کند، قبل از ساخت جدول‌ها و انتقال دیتا پشتیبان می‌گیرد.
- D1 علاوه بر این قابلیت Time Travel دارد (بازگردانی به هر لحظه از ۷ روز اخیر در پلن رایگان، ۳۰ روز در پلن پولی): `npx wrangler d1 time-travel restore <دیتابیس> --timestamp=<زمان>`.

بازگردانی از فایل پشتیبان (روی یک دیتابیس خالی):
```bash
npx wrangler d1 execute <دیتابیس> --remote --file=backups/<فایل>.sql
```

## برگشت به سرور قبلی (Rollback)
```bash
curl "https://api.telegram.org/bot<STORE_TOKEN>/deleteWebhook"
curl "https://api.telegram.org/bot<MONSHI_TOKEN>/deleteWebhook"
```
بعد ربات‌های قدیمی را دوباره روشن کنید. (داده‌هایی که بعد از انتقال روی Cloudflare ثبت شده به سرور قدیمی برنمی‌گردد.) پیشنهاد: سرور قدیمی را یک هفته نگه دارید. کانال پل قدیمی دیگر لازم نیست.

## محدودیت‌های پلن رایگان و طراحی بر اساس آن‌ها

| محدودیت (Free) | مقدار | راه‌حل در کد |
|---|---|---|
| زیردرخواست در هر اجرا (تلگرام + Gemini + **کوئری D1**) | ۵۰ | هر اجرا یک «بودجه‌شمار» دارد؛ حلقه‌ها قبل از اتمام بودجه می‌ایستند و کار باقی‌مانده به Cron بعدی می‌رود |
| CPU در هر درخواست | ۱۰ میلی‌ثانیه | بدون کار سنگین؛ embeddingهای decode‌شده کش می‌شوند |
| ردیف خوانده‌شده D1 | ۵ میلیون در روز | همه‌ی کوئری‌های پرتکرار ایندکس دارند (تست `indexes.test.ts`)؛ تنظیمات/FAQ هر درخواست یک بار خوانده می‌شود |
| ردیف نوشته‌شده D1 | ۱۰۰ هزار در روز | نشست بدون تغییر ذخیره نمی‌شود؛ پرچم‌ها دسته‌ای نوشته می‌شوند |
| Cron Trigger | ۵ تا | فقط یکی (`* * * * *`) |

نتیجه‌ی عملی:
- **اطلاعیه‌ی همگانی** دسته‌ای ارسال می‌شود (حدود ۴۰ نفر در دقیقه). برای ۱۰۰۰ مشتری حدود ۲۵ دقیقه؛ در پایان گزارش به ادمین می‌رسد.
- **رسید** برای همه‌ی ادمین‌ها کپی می‌شود (هر ادمین یک زیردرخواست). تا حدود ۳۰ ادمین پشتیبانی می‌شود.
- **یادآوری اشتراک** ساعت ۱۱ تهران شروع می‌شود و اگر تعدادشان زیاد باشد در دقیقه‌های بعد ادامه می‌یابد (هر مشتری دقیقاً یک بار).
- مصرف تخمینی برای یک فروشگاه کوچک (۲۰۰۰ پیام فروشگاه + ۱۰۰۰ پیام Business در روز): کمتر از ۱۰٪ سقف رایگان.

اگر روزی به سقف رسیدید، پلن Workers Paid (۵ دلار در ماه) سقف زیردرخواست را ۱۰٬۰۰۰ و CPU را ۳۰ ثانیه می‌کند — **بدون هیچ تغییری در کد**.

## نکته‌ها و عیب‌یابی

- **چک‌لیست سفارش** (`sendChecklist`) به اکانت Premium نیاز دارد؛ در غیر این صورت خودکار به پیام متنی وضعیت برمی‌گردد.
- **Gemini**: اگر در لاگ `User location is not supported` دیدید، آن منطقه پشتیبانی نمی‌شود؛ ربات بی‌صدا به تطبیق کلیدواژه‌ای برمی‌گردد و چیزی خراب نمی‌شود. زمان‌بندی هر تماس ۸ ثانیه است.
- **Business Mode** باید در BotFather روشن و اتصال از **Settings → Chat Automation** انجام شده باشد، وگرنه منشی پیامی نمی‌بیند.
- مشتری‌ای که هرگز با حساب پشتیبانی چت نکرده باشد: پیام «در حال آماده‌سازی» از طرف خود ربات فروشگاه ارسال می‌شود و ادمین دکمه‌ی دستی «✅ تحویل شد» می‌گیرد (مثل قبل).
- `/setup` را بعد از هر تغییر توکن یا آدرس دوباره باز کنید.
- بعد از تغییر `[vars]` در `wrangler.toml` باید دوباره `npm run deploy` کنید.

## توسعه و تست محلی

```bash
npm run typecheck          # بررسی TypeScript
npm test                   # همه‌ی تست‌ها (تلگرام و D1 شبیه‌سازی می‌شوند)
npm run build:check        # بسته‌بندی Worker بدون deploy

# اجرای محلی در workerd
cp .dev.vars.example .dev.vars   # توکن‌ها و WEBHOOK_SECRET را پر کنید
npm run db:migrate:local
npm run dev                      # سپس: curl "http://localhost:8787/__scheduled?cron=*+*+*+*+*"
```

تست‌ها شامل: جریان کامل خرید، کد تخفیف، خرید دستی با لینک یک‌بارمصرف، صف و مخاطبان اطلاعیه، ویرایش محصول و لیست انتظار، دلیل رد و رسید تکراری، گزارش فروش، دعوت دوستان، تاپیک‌ها، کارت مشتری، جواب از نوتیف، Cron، خط لوله‌ی پیام‌های منشی، Gemini (با fetch ساختگی)، پنل‌های مدیریتی، پل مستقیم و مسیر جایگزین آن، احراز هویت webhook، بودجه‌ی ۵۰ تماس، ایندکس‌ها، و انتقال دیتا.

src/lib/                 بودجه، نشست D1، ویزارد، زمان/تقویم شمسی

src/store/suppliers/     تأمین‌کننده: adapter آریوباکس، همگام‌سازی، موتور سفارش (engine.ts)، کارت تصمیم، اکانت‌های من، کیف پول

## امنیت

- webhookها با هدر `X-Telegram-Bot-Api-Secret-Token` محافظت می‌شوند؛ بدون آن پاسخ ۴۰۱ است.
- توکن‌ها و کلیدها فقط در `wrangler secret` (و `.dev.vars` محلی که در گیت نیست) نگهداری می‌شوند.
- `.env`، `*.db`، `migration_out/` و `backups/` در `.gitignore` هستند. مخزن عمومی است؛ هیچ داده‌ی مشتری یا کلیدی را commit نکنید.
